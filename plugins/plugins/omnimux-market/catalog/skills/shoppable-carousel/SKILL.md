# Shoppable Carousel 通用商品轮播图工作流

## 随附资产

本技能自带以下文件，按需读取，不要凭记忆复述：

| 文件 | 何时读取 |
| --- | --- |
| `references/playbook-index.md` | 选方案前先看方案库索引 |
| `references/categories/{beauty,fashion,home}.md` | 商品属于美妆个护 / 服饰配饰 / 家居生活时，读对应品类方案 |
| `references/common-rules.md` | 每次规划都要遵守的通用规则 |

| `examples/generic-example.md` | 需要一份完整示例时 |

## 1. 任务目标与适用范围

本工作流用于根据商品图片和已确认的商品信息，规划电商商品轮播图。

适用场景：

- TikTok Shop 商品轮播图
- 电商详情页图片
- 商品卖点展示图
- 服饰、饰品、美妆、家居、食品、电子产品等商品视觉规划
- AI 商品图片生成前的页面方案设计

不适用场景：

- 完整 A+ 详情页长图
- 视频脚本或视频分镜
- 纯品牌海报
- 未提供任何商品参考的虚构商品生成

核心原则：

1. 先识别商品，再选择图片方案。
2. 只使用图片中可确认的信息。
3. 不把所有商品都套用同一种“主图—卖点—对比—CTA”结构。
4. 每一页必须有明确的可见信息。
5. 商品主体、颜色、结构、件数和关键细节必须保持一致。
6. 需要生成图片时，每张图片独立生成。
7. 所有生成结果必须经过数量、内容和格式检查。

## 2. 输入要求

### 必要输入

至少需要：

- 一张或多张商品图片
- 商品名称，或用户对商品的简要描述

### 可选输入

- 商品类目
- 商品卖点
- 商品规格
- 商品尺寸
- 商品颜色或款式
- 目标市场
- 目标语言
- 目标平台
- 是否需要人物
- 是否需要生成图片
- 是否需要打包 ZIP

### 信息分级

所有商品信息必须分成三类：

#### 直接可见

可以从图片中直接确认的信息，例如：

- 商品颜色
- 商品形状
- 可见材质表现
- 可见包装文字
- 可见数量
- 可见按钮、拉链、扣件、图案
- 图片中的人物姿态
- 图片中的使用场景

#### 用户确认

由用户明确提供的信息，例如：

- 商品尺寸
- 产品成分
- 材质名称
- 功能
- 适配型号
- 套装内容
- 颜色名称
- 使用方法

#### 未知

目前无法确认的信息，例如：

- 图片未展示的背面结构
- 未提供的尺寸
- 未展示的内部内容
- 未确认的功效
- 未确认的兼容性
- 未提供的包装数量

未知信息不得被当作事实写入画面。

## 3. 商品图片识别流程

1. 查看全部商品图片。
2. 记录商品主体。
3. 记录颜色、形状、结构和数量。
4. 记录可见包装、标识和文字。
5. 区分商品本体与场景道具。
6. 标记无法确认的部分。
7. 建立商品保真约束。

### 商品保真约束示例

```text
必须保持：
- 商品主体外形
- 商品颜色
- 可见图案
- 可见商标
- 扣件和缝线
- 商品数量
- 包装比例
- 关键结构

不得擅自增加：
- 未展示的配件
- 未确认的颜色
- 未确认的功能
- 未确认的成分
- 未确认的尺寸
- 未确认的认证
- 未确认的赠品
```

## 4. 方案选择规则

先判断商品的细分类型，再选择方案。

### 方案选择优先级

1. 商品最容易被看懂的视觉方式
2. 商品最重要的可见特征
3. 当前素材能否完整支持该方案
4. 页面之间是否具有统一性
5. 是否适合目标平台和目标用户

### 常见方案类型

#### 方案 A：商品外观展示

适合：

- 包装商品
- 饰品
- 家居用品
- 电子产品
- 小型工具

典型页面：

1. 商品整体
2. 细节局部
3. 使用场景
4. 包装或配件
5. 尺寸或规格说明

#### 方案 B：人物使用展示

适合：

- 服饰
- 配饰
- 美妆工具
- 个护用品
- 可穿戴产品

典型页面：

1. 人物整体使用
2. 局部细节
3. 使用动作
4. 不同角度
5. 搭配或选择参考

#### 方案 C：场景解决方案

适合：

- 家居用品
- 厨房用品
- 收纳用品
- 清洁用品
- 办公用品

典型页面：

1. 商品进入场景
2. 使用动作
3. 功能细节
4. 场景结果
5. 规格与适用位置

#### 方案 D：款式或颜色选择

适合：

- 服饰
- 饰品
- 美妆色号
- 手机配件
- 家居颜色款

典型页面：

1. 主款展示
2. 多款并列
3. 局部细节
4. 搭配展示
5. 选择提示

## 5. 轮播图页面规划规则

每张图片必须记录以下字段：

- 页面编号
- 图片类型
- 销售作用
- 景别
- 机位
- 主体动作
- 场景
- 背景道具
- 内部版式
- 图内文案
- 商品保真要求
- 禁止生成内容

### 页面规划模板

```text
第 01 页
图片类型：
销售作用：
景别与机位：
主体动作：
场景：
背景道具：
内部版式：
图内文案：
商品保真要求：
禁止内容：
```

### 图片类型与销售作用必须分开

图片类型描述画面实际出现的内容，例如：

- 商品正面图
- 手持商品
- 人物上身
- 桌面俯拍
- 局部细节
- 包装展示
- 使用场景

销售作用描述该页帮助用户完成什么，例如：

- 吸引停留
- 看清外观
- 理解使用方法
- 对比款式
- 辅助选择
- 解释规格

## 6. 文案与合规约束

### 文案原则

- 文案必须与画面相对应。
- 每页优先使用一个短标题。
- 必要时添加一个简短标签。
- 不堆叠多个未经证明的卖点。
- 不虚构用户评价。
- 不虚构销量或排名。
- 不虚构限时促销。
- 不虚构专家背书。
- 不虚构测试结果。
- 不生成图片中不存在的规格。

### 推荐文案结构

```text
短标题：
不超过一行，说明当前画面重点。

辅助标签：
只在必要时使用，用于补充颜色、款式或使用动作。

说明文字：
仅用于规格、尺寸或已确认信息。
```

### 风险文案替换

| 高风险写法 | 更稳妥写法 |
|---|---|
| 100% 有效 | 展示产品使用场景 |
| 最强、第一 | 突出可见设计特点 |
| 永久有效 | 根据已确认的产品信息描述 |
| 专业认证 | 仅在用户提供认证依据时使用 |
| 立刻见效 | 改为“展示使用方式” |
| 用户都在买 | 改为“商品展示” |

## 7. 生图调用流程

如果用户只需要方案：

- 输出完整逐图规划。
- 不生成图片。

如果用户明确要求生成图片：

1. 确认商品参考图。
2. 确认页面数量。
3. 确认目标语言。
4. 确认图内文案。
5. 为每一页生成独立提示词。
6. 每张图片使用一个独立生成任务。
7. 所有页面重复商品保真要求。
8. 统一人物、场景、光线和视觉风格。
9. 生成前进行付费确认。
10. 生成完成后逐页检查。

### 单图提示词结构

```text
商品参考：
[商品身份与来源]

商品保真要求：
[必须保持的颜色、结构、数量、图案和比例]

画面类型：
[本页图片类型]

镜头：
[景别、机位、焦段感和构图]

主体动作：
[人物或商品的动作]

场景：
[背景与环境]

光线：
[光线方向、软硬和色温]

内部版式：
[单图、局部放大、对照、图文卡等]

图内文字：
[确切文字，不允许自动改写]

禁止内容：
[不得出现的商品、配件、人物、结构或虚假信息]

输出要求：
[电商视觉、清晰商品主体、统一风格、适合目标平台]
```

## 8. 生成结果检查

每张图片都必须检查：

### 商品检查

- 商品颜色是否正确
- 商品结构是否正确
- 数量是否正确
- 图案是否变形
- 商标是否被错误修改
- 是否增加了不存在的配件
- 是否改变了包装文字

### 画面检查

- 人物手部是否正常
- 商品是否被遮挡
- 动作是否符合页面目的
- 场景是否统一
- 光线是否统一
- 页面是否重复
- 图内文字是否完整
- 文案是否清晰可读

### 结果状态

每张图片标记为：

```text
通过
需要修正
生成失败
无法确认
```

不通过的页面必须单独修正，不得用其他页面替代。

## 9. 文件命名与打包规则

### 文件命名

使用以下格式：

```text
01_<short-slug>.<extension>
02_<short-slug>.<extension>
03_<short-slug>.<extension>
```

示例：

```text
01_product-hook.png
02_detail-view.png
03_usage-scene.png
04_style-options.png
```

命名要求：

- 使用两位数字编号。
- 按轮播顺序编号。
- 使用英文小写。
- 使用短横线分隔。
- 不使用中文。
- 不使用随机任务编号。
- 不使用长提示词。
- 保留原始文件格式。
- 文件名必须唯一。

### ZIP 文件命名

```text
<product-slug>-tiktok-carousel.zip
```

如果没有产品名：

```text
tiktok-carousel-set.zip
```

### 打包前检查

- 预期图片数量是否完整
- 每张图片是否存在
- 每张图片是否可读取
- 每张图片是否通过内容检查
- 是否有重复页面
- 是否混入参考图
- 是否混入失败图
- 是否混入提示词或日志文件

```text
已完成：

- 通过检查：
- 需要修正：
- 文件格式：

图片清单：
1. 01_product-hook.png
2. 02_detail-view.png
3. 03_usage-scene.png
```

### 交付 ZIP

```text
已完成：
- 独立图片数量：
- ZIP 内图片数量：
- 文件命名：
- 完整性校验：
- 图片格式校验：
```

只有所有预期图片都存在并通过检查时，才能称为完整套图。
