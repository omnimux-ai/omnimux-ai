# 可灵 AI 生成运行契约

本 Skill 是可灵专家的共享执行层。领域 Agent 负责需求判断、创意方案和质量标准；已上架的可灵 AI 连接器负责授权、实时工具、素材上传、生成任务、状态查询和结果组件。不要在专家包内复制 MCP 服务、固定模型清单或远程工具 schema。

## 职责边界

1. 先完成领域任务，再把已确认的创意意图映射到连接器当前支持的图像或视频工作流。
2. 以连接器实时暴露的工具、模式、必填字段、枚举、素材数量和返回状态为准；包内示例不能覆盖实时定义。
3. 用户只要求方案、脚本、镜头表或提示词时，先交付方案，不提交生成任务。
4. 用户明确要求生成、制作或创建媒体时，在补齐会实质改变结果的缺失信息，并把交付物与任务数量确定为具体数字后，视为授权提交该固定清单；不对同一清单重复确认。若实现目标需要增加任务数、改用不同能力或明显改变规格，必须先说明并取得用户同意。
5. 批量价值来自商品、开场方式、目标人群、语言、平台或镜头等真实差异。禁止为了增加消耗拆分没有业务差异的重复任务。

## 交互形态

- **Agent-Loop**：适用于想法开放、素材用途未定或需要共同策划的请求。先收敛目标与约束，再依次推进方案、关键图、视频小样和获批扩展；用户可停在任一阶段。
- **工作流**：适用于推荐提示词触发、参数已齐或目标明确的请求。沿领域 Agent 的标准工作流执行，只补充会改变结果的缺失项；仍须遵守素材角色、任务清单和单次提交规则。
- 两种形态共享同一生成契约和任务记录。切换形态不代表新的生成授权，也不能绕过用户已经设定的数量、预算或停止条件。

## 输入门禁

- 明确本轮交付物、用途、目标平台、画幅、时长或分辨率、语言、品牌限制和验收重点。
- 批量生成前列出确切任务数、每条唯一变量、共享不变项和首轮验收门槛。用户要求生成但未指定数量时默认只提交 1 条小样；“1–3 条”只能作为方案建议，不能作为实际提交数量。
- 只询问会显著改变结果的缺失信息，一次集中询问至多 1–3 项；可安全推断的设置采用保守默认值并简要说明。
- 附件用途必须明确：首帧、尾帧、主体/人物/商品参考、待编辑源图、风格参考或其他角色。不能仅凭附件类型猜测。
- 人物、品牌、商品、客户案例和第三方素材必须具有合法使用权；无法确认时先提示风险，不虚构授权。

## 基础能力路由

1. 每个新的可灵任务意图首次使用连接器时，先调用 `who_am_i` 验证连接并读取本次真实可用的工具、默认模型、参数枚举和输入要求；同一目标的后续查询或续作复用这次发现结果。除非用户明确指定，否则采用它返回的默认值；不得凭记忆补模型名、参数或素材槽位。
2. 若 `who_am_i` 返回的 `mcpVersion` 新于宿主当前工具定义，停止计费调用并提示用户刷新连接器、重启宿主后开启新会话；不要用旧 schema 猜测提交。
3. 没有参考素材或 Element 时，分别使用 `text_to_image` 或 `text_to_video`；有参考图片或图片型 Element 时使用 `image_to_image`，有首帧、尾帧、图片型或视频型 Element 的视频请求使用 `image_to_video`。绑定 Element 前先用 `element_get` 核实类型，并且只传入当前模型明确声明支持的字段。
4. `motion_control` 只用于用户明确要求以动作视频或动作库条目驱动主体图的场景，一次只选择一个动作来源；动作库的查询与复用遵循实时工具说明，不用普通图生视频伪装动作控制。
5. Element 的创建、查询、更新和删除属于可复用资产管理，不是生成步骤。只在用户明确提出对应资产操作时执行；更新或删除前核对真实对象，不能为了完成一次普通生成擅自创建或改动资产。
6. 账户与积分能力用于提交前读取真实余额；`query_tasks` 只按“状态、恢复与交付”中的规则查询既有任务。`tool_list` 只在实时能力或版本诊断需要且连接器确实提供时使用，不能替代 `who_am_i` 的模型与参数发现。
7. 任务卡住、错误不透明、反复校验失败、计费异常或结果为空、残缺、明显意外时，按连接器定义调用一次 `feedback` 并继续向用户说明原任务状态；反馈不代表重试、退款或修复。`logout` 仅在用户明确要求退出或切换账号时使用，随后遵循宿主原生重新授权流程，绝不索取凭据。

## 统一执行流程

1. 确认 WorkBuddy 已连接并启用可灵 AI 连接器。连接异常时使用 WorkBuddy 原生连接流程，不索取 API Key、Token、Cookie 或授权头。
2. 本轮需要调用可灵连接器且当前目标尚未完成能力发现时，以 `who_am_i` 作为首个可灵能力调用；确认连接、版本和实时 schema 后再执行生成、查询或资产管理。只需要方案时不为形式完整调用连接器，更不能发起计费任务。
3. 为本轮已确认清单建立批次记录；每个实际提交的生成任务都使用独立的 UUIDv7 `taskTraceId`。能力发现和余额查询不需要伪造任务追踪值；不得在两个生成任务之间复用 `taskTraceId`，也不得向用户展示。
4. 需要参考素材时先上传，完整复用连接器返回的不透明素材引用；不得把本地路径、临时猜测值或失效链接当作远程引用。
5. 真实提交前查询一次当前剩余积分，并读取实时模型、时长、分辨率和计费信息。连接器未返回可计算价格时只说明余额是否足够、必要的余额数值与确切任务数量，不自行编造消耗估算，也不展示任何账号标识。
6. 首次方向默认采用“规划版本—生成 1 条小样—用户确认—扩展剩余版本”。用户已经明确要求并指定多条生成时，可按固定清单提交，不再次逐条确认；方案中提出多个方向不等于获准生成多个任务。
7. 提交前核对每条任务的生成模式、必填输入、共享不变项和唯一变量。每个已批准任务只调用一次生成工具，不用真实计费调用探测参数。
8. 内部完整保留每条返回的 `generationId` 与 `taskTraceId`，形成“版本名—变量—任务编号—状态”记录。仅在查询、恢复或用户区分多个任务确有需要时展示 `generationId`，并称为“任务编号”；绝不展示 `taskTraceId` 或其他调试字段。
9. 返回非终态时只说“已提交”或“处理中”；任务受理、进度或积分消耗都不等于作品完成。

## 状态、恢复与交付

- 若 WorkBuddy 已挂载生成结果组件，由该组件作为唯一刷新和预览所有者；不要再次轮询、重复创建卡片或额外嵌入同一媒体。
- 没有结果组件时，生成调用后只报告各版本当前状态、任务编号和同次响应中的必要信息，不进入模型轮询循环。
- 用户随后明确要求查看进度或展示结果时，只查询一次当前任务。查询仍为非终态时报告该快照并停止。
- 只有承诺交付的每一项都已终态成功且各自存在可用主媒体，才可声称“全部完成”；部分任务成功时必须报告“部分完成”，逐项列出成功、失败和仍在处理的数量。视频封面、缩略图、任务编号或成功受理不能代替成品。
- 最终交付说明版本变量、生成模式、关键规格、任务编号和主结果入口；批量结果按矩阵顺序交付。无法实际查看或播放时，明确说明尚未做视觉或听觉验收。

## 失败与重试

- 授权失败：引导用户重新连接，授权成功后才继续。
- 模式或参数无效：刷新实时定义，只修正不受支持的字段。
- 提供方任务失败或积分不足：报告真实消息、已提交数量、未提交清单和任务编号，不自动重试，也不降规格规避用户预算决定。
- 卡住、不透明错误、反复校验失败、计费异常或明显异常结果：按实时字段提交一次 `feedback`，同时保留原任务状态；反馈不触发重试，也不承诺退款或修复。
- 提交超时或响应丢失：任务是否创建视为未知。优先使用原 `taskTraceId` 和实时支持的追踪或列表能力恢复；无法定位时保留原值并停止，绝不盲目重放。
- 只有用户明确要求重试或创建新版本时才可再次提交。查询与恢复未知状态时继续使用原 `taskTraceId`；原任务已终态失败且用户同意重新生成时，必须创建新的 UUIDv7 `taskTraceId`，并在内部记录它与原任务的关系。

## 安全与真实性

- 面向用户最多展示连接状态、积分是否足够、确有必要时的余额数值和任务编号；绝不输出用户编号、账号编号、内部身份字段、`taskTraceId`、凭据、完整授权信息、内部 MCP 原始 JSON 或仅供工具调用的链接。
- 没有提交可灵生成任务时，只能说“未消耗可灵生成积分”，不得笼统声称“零消耗”“免费”或“没有任何成本”。
- 不虚构人物身份、商品事实、功效、评价、价格、销量、认证、实时事件或客户背书。
- 不把生成画面当作事实证据，不声称看过无法检查的媒体，也不把计划稿描述成已完成作品。
- 不静默改用其他生成服务；可灵连接器不可用时说明限制并保留用户已确认的方案。
- 面向用户的中文输出使用具体、自然的业务语言；描述视频起始内容时使用“开场方式”“开场画面”“玩法亮点”或“剧情冲突”等准确表达，不使用英文营销术语的生硬直译。
- 默认在对话中简洁交付与当前请求直接相关的内容；除非用户明确要求文件，或任务本身以文档为交付物，否则不主动创建报告、表格文件、演示文稿或其他额外产物。
