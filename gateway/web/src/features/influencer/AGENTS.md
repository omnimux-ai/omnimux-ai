# Character workbench

- MUST derive ordinary image creation from the user's actual inputs: no reference image means text generation; an uploaded reference means style reference. Do not expose a manual image-mode selector.
- MUST use uploaded references as style inspiration for a newly created character, not as an instruction to edit the uploaded image. Keep the separate existing multi-view derivation semantics intact.
- MUST NOT add generation controls or editing entry points merely because the underlying service supports them; new user-facing actions require an explicit product requirement.
- MUST create new browser character images from the existing character selections and optional style reference, without a free-description input. Keep new creation `brief` empty across draft, preset, history reuse and final submission; retain original historical text, video descriptions and separate multi-view semantics. Empty human selections without a reference remain invalid; do not invent hidden placeholder text or random replacements.
- MUST NOT restate reference-video metadata (raw duration, generated duration, aspect ratio, file name) in the parameters or any settings card when the media slot already shows it; show each value once, at the decision point, and prefer a state badge over a sentence.
- MUST NOT explain automatic workbench behavior (auto-follow duration/frame, auto-detect, auto-trim, auto-retry) in the panel. Render state values only; any hint must pass the copy admission rules in [web/AGENTS.md §3.17](../../../AGENTS.md#317-ui-文案极简与提示准入).
- Copy admission: the workbench defaults to no explanatory copy. New visible hints require the action test in [web/AGENTS.md §3.17](../../../AGENTS.md#317-ui-文案极简与提示准入); "clearer" or "more complete" is not a reason to keep one.
- Blocking failures MUST surface on the triggering action through the shared `toast.error` (top-center `Toaster`), never as inline red copy inside a card; how-to guidance belongs in the field `placeholder` or an existing tooltip, not in an added panel paragraph.
- Place hints on the ladder from [web/AGENTS.md §3.17](../../../AGENTS.md#317-ui-文案极简与提示准入): state value → placeholder → tooltip → toast → inline (never). Disabled reasons live in the disabled control's `title` + `aria-describedby`; overall unavailability is expressed on the CTA itself, not in a status paragraph; one failure surfaces once.
- Look ownership: a lock exists only where the visitor picked by hand. Only `pick()` may write locks; every whole look (preset, saved task, `?recreate=`, landing or pre-login draft) MUST go through `applyLook()` and MUST NOT translate values into locks. Randomization fills unlocked categories only and never overwrites a lock. The session is in-memory: a route remount keeps it, a reload starts over, and nothing may persist it to storage.
