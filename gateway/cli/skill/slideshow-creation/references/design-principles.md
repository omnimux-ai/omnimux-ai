# Design Principles — 图文设计原则

供 l2-creative-agent、l2-image-agent、l2-script-agent 在规划阶段引用的通用设计约束。
与 `visual-presets.md` 配合使用：预设定义"什么风格"，本文档定义"怎么做好"。

---

## 1. 视觉层级原则

| 原则 | 说明 |
|------|------|
| **单焦点** | 每页只有一个主导元素最先吸引视线 |
| **尺寸对比** | 标题 ≥ 正文的 2-3 倍，制造层级差 |
| **呼吸空间** | 边距 ≥ 10%，留白是设计的一部分 |
| **Z 型阅读** | 视线引导：左上 → 右上 → 左下 → 右下 |
| **三分法** | 关键元素放在 1/3 交叉点，而非正中央 |

---

## 2. 受众 → 信息密度映射

根据 slideType 和目标受众选择合适的信息密度。

| 受众/场景 | 推荐密度 | 每页内容量 | 说明 |
|----------|---------|-----------|------|
| 高管/决策者 | minimal | 1 个核心观点 | 结论先行，尊重时间 |
| 初学者/入门 | minimal → balanced | 1 个概念 | 逐步递进，视觉隐喻优于抽象图表 |
| 一般受众 | balanced | 2-3 要点 | 信息量适中，可读性优先 |
| 专业受众 | balanced → dense | 3-5 要点 | 可承受更多数据/细节 |

**密度与页面类型的关系**：
| 页面类型 | 推荐密度 |
|---------|---------|
| Cover/Hook | minimal（抓注意力） |
| 正文/论证 | balanced（信息传递） |
| 数据/对比 | dense（高信息密度） |
| 引用/金句 | minimal（情绪冲击） |
| CTA/总结 | balanced（清晰行动） |

## 3. 排版规范

### 标题层级

| 元素 | 处理方式 |
|------|---------|
| 主标题 | 粗体，正文的 2-3 倍大小，叙事式（非标签式） |
| 副标题 | 中等粗细，补充上下文 |
| 正文 | 常规字重，可读尺寸 |
| 数据标签 | 偏小，辅助信息 |
| 强调 | 用粗体或颜色，不用下划线 |

### 叙事式标题 vs 标签式标题

| 差 (标签式) | 好 (叙事式) |
|------------|-----------|
| "关键数据" | "6个月用户翻倍" |
| "我们的方案" | "一个平台替代五个工具" |
| "优势" | "每周省下10小时" |
| "产品特点" | "99%纯水·三零添加" |

### 中英文字体方向

排版描述应使用视觉特征而非字体名称（用于 AI 生图 prompt）。

| 场景 | 英文方向 | 中文方向 |
|------|---------|---------|
| 技术/精确 | 几何无衬线、锐利边缘 | 现代黑体、干净等宽感 |
| 编辑/优雅 | 高对比衬线、经典比例 | 宋体、书法气质 |
| 亲切/温暖 | 圆润无衬线、友好弧度 | 楷体/手写感、温润笔触 |
| 商务/权威 | 几何无衬线、中等粗细 | 商用黑体、稳重结构化 |

## 4. 色彩选择原则

**内容优先法**：
1. 分析内容主题、情绪和行业
2. 对照预设色板或受众期望
3. 确保标题 vs 背景对比度 ≥ 4.5:1（WCAG AA）
4. 全套图文最多 3-4 色，保持一致

**内容类型 → 色彩情绪**：
| 内容类型 | 推荐色调 |
|---------|---------|
| 技术/架构 | 冷色（蓝/青/灰） |
| 教育/友好 | 暖色（橙/黄/绿） |
| 商务/专业 | 中性（藏蓝/金/灰） |
| 创意/艺术 | 高饱和（紫/红/青） |
| 科学/医学 | 冷色或中性 |
| 娱乐/游戏 | 暗色或高饱和 |

## 5. 布局词汇表

供 l2-image-agent 的 `layoutSuggestion` 字段标准化使用。

### 通用布局

| 布局 | 描述 | 适用 |
|------|------|------|
| `title-hero` | 大标题居中 + 副标题 | Cover/Hook 页 |
| `split-screen` | 半图半文，左右或上下分割 | 产品特性、对比 |
| `image-caption` | 满幅图 + 文字叠加 | 视觉故事、情绪页 |
| `key-stat` | 单个大数字为焦点 | 数据冲击、指标 |
| `icon-grid` | 图标网格 + 标签 | 功能、优势、好处 |
| `two-columns` | 双栏平衡排列 | 双要点、配对信息 |
| `three-columns` | 三栏排列 | 三要点、分类对比 |
| `bullet-list` | 结构化要点列表 | 简单内容、清单 |
| `quote-callout` | 引用高亮 + 来源 | 金句、用户评价 |

### 信息图表类布局

| 布局 | 描述 | 适用 |
|------|------|------|
| `linear-progression` | 从左到右顺序流 | 时间线、步骤 |
| `comparison` | 并列 A vs B | 对比、前后 |
| `hub-spoke` | 中心节点 + 辐射 | 概念图、生态 |
| `funnel` | 漏斗逐步收窄 | 转化、筛选 |
| `bento-grid` | 不等大小瓷砖 | 总览、摘要 |
| `dashboard` | 指标 + 图表组合 | KPI、数据展示 |
| `flow-chart` | 流程节点 + 箭头 | 流程、决策树 |

### 布局与页面角色的匹配

| 页面角色 | 推荐布局 |
|---------|---------|
| hook | `title-hero`, `image-caption`, `key-stat` |
| problem | `split-screen`, `comparison` |
| solution/feature | `split-screen`, `icon-grid`, `two-columns` |
| evidence | `key-stat`, `dashboard`, `quote-callout` |
| benefit | `icon-grid`, `three-columns`, `bullet-list` |
| usage | `image-caption`, `bento-grid` |
| cta | `title-hero`, `quote-callout` |

### 布局选择常见错误

- 用三栏布局放两个要点（留下空栏）
- 图表堆在文字下方（应并排）
- 在无真实图片时使用 image-caption 布局
- 在非引用场景使用 quote-callout（仅用于真实引用）

## 6. 一致性要求

全套图文必须在以下维度保持统一：

| 维度 | 要求 |
|------|------|
| **色调** | 整套使用同一预设色板，不跨预设混用 |
| **字体风格** | 同族字体，标题/正文层级一致 |
| **视觉语言** | 图标风格统一（线性/填充/手绘择其一） |
| **间距** | 全套边距/内距一致 |
| **图片处理** | 滤镜/裁切/叠加方式统一 |
| **装饰元素** | 同一套形状/线条/纹理贯穿全套 |

## 7. 内容规则

### 7.1 每页单一信息
- 一页传达一个核心观点
- 删除冗余信息，清晰 > 全面

### 7.2 叙事式标题（强制）
- 标题讲故事，不是打标签（见第3节示例）
- 读标题就能理解全页核心信息

### 7.3 避免 AI 味
去除以下模式：
- "让我们来看看"、"深入了解"、"探索"
- "令人兴奋的"、"革命性的"
- "总结一下"、"综上所述"
- 过度使用 emoji、感叹号堆叠

### 7.4 有意义的尾页
不要只写"谢谢"或"关注我"，至少包含一个：
- 清晰的行动号召（具体动作）
- 令人记住的核心观点
- 引发思考的收尾问题
- 有目的的互动引导

### 7.5 自包含描述
- 每页的 imageHint / visualDirection 必须完整描述，不引用其他页
- "参考第2页风格"这类跨页引用是禁止的
- 所有色彩、构图、内容在描述中显式写出
